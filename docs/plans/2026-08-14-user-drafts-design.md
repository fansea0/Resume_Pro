# 模板主页与我的草稿设计

## 目标

登录成功后，用户默认进入模板主页；从顶部导航进入“我的草稿”，只查看当前租户已保存的简历，并能一键继续编辑。

## 已确认的交互

- 模板主页是登录后的默认页，模板卡继续作为“以此模板开始编辑”的入口。
- 顶部导航提供“模板主页”和“我的草稿”。
- 我的草稿页展示当前账号保存的简历：标题、所选模板和最近更新时间。
- 点击一份草稿直接打开编辑器，并载入该草稿的内容与已选模板。
- 编辑器保留保存、导出、删除与返回模板主页能力，并增加返回草稿页的明确入口。

## 架构

前端 `App` 的视图状态扩展为 `gallery`、`drafts`、`editor`，不增加路由依赖。认证完成后默认使用 `gallery`；退出或会话过期时回到未认证状态。

新增 `ResumeDrafts` 展示组件。它调用已有的 `listResumes()`；该 API 已通过 JWT 中的 `tenant_id` 执行后端隔离，因此前端不传用户或租户 ID，也不会暴露其他用户的草稿。组件把所选 `StoredResume` 回调给 `App`，由 `documentFromStored()` 转为编辑器所需的 `ResumeDocument`。

`ResumeLibrary` 仍是编辑器内的保存与导出控制面板，不承担跨页面的草稿总览。创建或更新后，用户回到“我的草稿”时由页面重新拉取最新列表，保证标题和更新时间正确。

## 失败处理与空状态

- 加载时显示“正在加载草稿…”。
- 加载失败显示可理解的错误文案，且保留导航以便回到模板主页。
- 无草稿时显示空状态，并提供“去选择模板”按钮。
- 草稿内容损坏时不进入编辑器，显示“无法读取该简历内容”。

## 测试策略

- 为 `ResumeDrafts` 写 RTL 测试：加载、空状态、失败状态、元数据展示及点击回调。
- 扩展应用集成测试：登录后默认模板主页，导航到草稿页，点击草稿载入编辑器，空状态可返回模板主页。
- 运行完整前端 Vitest 套件与生产构建；不改动已有租户 API 或后端迁移。
