# 模板后台管理设计

## 目标

为管理员账号提供模板管理页面。管理员可查看全局模板并删除模板；普通登录用户既看不到入口，也无法调用管理接口。

## 授权模型

`users` 增加不可由客户端写入的 `is_admin` 布尔字段，默认 `false`。管理员角色仅由数据库字段管理，不提供公开的角色修改接口。

JWT 增加 `is_admin` 声明，认证中间件将它放入 Principal。`GET /api/auth/me` 返回该标记，以便前端仅对管理员展示后台入口。管理路由仍在服务端基于 JWT 角色执行鉴权；隐藏页面不是安全边界。

## 模板目录与删除语义

现有模板是前端随构建发布的静态注册表，不能安全地从浏览器直接删除源文件。因此后端新增 `disabled_templates` 持久化表，存储被管理员禁用的模板 ID 与时间。`GET /api/templates` 返回全局禁用状态；管理员通过 `DELETE /api/admin/templates/{templateID}` 禁用模板。

前端把后端禁用状态应用在模板主页：普通用户不再看到已禁用模板；管理员管理页仍显示所有模板和状态。已保存简历可继续读取与编辑，即使模板后来被禁用，避免历史简历损坏；用户不能从主页新建该模板。

## 页面与数据流

认证后的顶部导航仅在 `user.isAdmin` 时显示“后台管理”。管理页列出静态模板注册表的名称、说明、预览图与当前状态；删除动作先在浏览器确认，再调用管理 API，并刷新状态。失败显示可恢复的错误信息。

`App` 使用新增 `admin` 视图。首次加载并行获取当前用户和模板状态；状态失败时模板主页保持可用且显示全部模板，避免管理 API 暂时故障阻塞简历创建。

## 测试策略

- Go：迁移与管理员同步、JWT 角色、非管理员 403、管理员读取和禁用模板、重复删除幂等。
- React：普通用户无入口，管理员有入口；管理页列出模板、删除后状态更新；禁用模板不再出现在模板主页。
- 全量运行 `go test ./...`、前端 Vitest 与生产构建。
