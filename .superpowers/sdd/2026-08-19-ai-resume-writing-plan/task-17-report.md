# Task 17 Report: AI rewrite service

## Scope

Implemented and review-hardened the Task 17 AI rewrite service and its LLM
transport boundary.

- `backend/internal/ai/service.go`
- `backend/internal/ai/service_test.go`
- `backend/internal/llm/options.go`
- `backend/internal/llm/options_test.go`
- `backend/internal/llm/client.go`

- `backend/internal/llm/testing/fake.go`

The AI package remains a pure LLM/prompt layer. It imports neither auth nor
persistence packages. Target-job data crosses the boundary through the
AI-local `TargetJobContext` DTO; the HTTP task will map its persistence model
into that DTO.

## Resulting behavior

### Strict structured output

`RewriteSection` passes a typed `llm.JSONSchemaResponseFormat` option on every
attempt. The option includes the section-specific schema and `Strict: true`.

The real `llm.NewChatModel` adapter translates that application option through
the installed Eino OpenAI API, `openai.WithExtraFields`, to this request shape:

```json
{
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "summary_rewrite",
      "strict": true,
      "schema": {}
    }
  }
}
```

The repository's `FakeChatModel` decodes and records the same typed call
option. Service tests therefore assert the exact strict flag, schema name,
root type, `additionalProperties`, and required fields without a network call.
An `internal/llm` test independently asserts the translated OpenAI JSON shape.

### Prompt trust boundary

Only embedded templates, the validated section selector, and the generated
schema are placed in the system message. The following caller-controlled data
is serialized as one JSON user message:

- current section content;
- `TargetJobContext`, including JD requirements;
- user instructions.

There are no closable XML-style delimiters. Go's JSON encoder escapes markup
characters and newlines while preserving their decoded data. The adversarial
test supplies closing tags, newlines, and an instruction to ignore system
rules in all three inputs, then proves that none appears in the system message
and that the user message remains one decodable JSON value with the original
data intact.

### Retry configuration

`llm.LoadConfigFromEnv` now exposes `Config.MaxRetries`:

- default: `1`;
- accepted override: integer `0` through `10`;
- malformed, negative, overflow, or values above `10`: return
  `ErrInvalidMaxRetries`.

`ai.WithMaxRetries` supplies the validated value to `NewService`; zero disables
schema retries. The runtime/server wiring is intentionally left to its planned
dependency-injection task.

### Streaming, usage, and cancellation

- Eino `ChatModel.Stream` reasoning chunks become `thinking` events.
- Content chunks are accumulated and validated before a suggestion is emitted.
- Per-attempt token usage takes the maximum cumulative usage observed within
  that stream; successful retry usage is summed across attempts into
  `CallResult.TokensIn` and `TokensOut`.
- Schema failures receive one repair turn by default and the same strict
  response-format option on every attempt.
- Cancellation observed before terminalization closes the channel without a
  random `error` or `done` event.
- A non-cancelled outcome emits an ordered `suggestion|error`, `done` pair.
- Thinking events are best effort. Two buffer slots are reserved for the
  terminal pair so a slow consumer cannot stall stream completion.

### Response validation boundary

The local fallback validator is explicitly limited to the exact keyword subset
generated by `internal/ai/schemas` for rewrite responses:

- types: object, array, string, null;
- object keywords: properties, required, additionalProperties;
- array items.

It no longer claims generic JSON Schema number/integer support, so there is no
path that incorrectly accepts fractional numbers as integers. Provider-side
strict structured output is the primary constraint; local validation defends
against incompatible or non-compliant OpenAI-compatible providers.

## Fix round 2: real-adapter wire evidence

Review requested a wire-level assertion in addition to the typed FakeChatModel
option assertion. `TestNewChatModel_SerializesStrictJSONSchemaResponseFormat`
now constructs the real adapter returned by `llm.NewChatModel`, points it at a
loopback `httptest.Server`, performs one controlled completion, and captures
the outbound `POST /v1/chat/completions` body.

The captured JSON is decoded and independently asserts:

- `response_format.type == "json_schema"`;
- `response_format.json_schema.name == "summary_rewrite"`;
- `response_format.json_schema.strict == true`;
- schema root type and `additionalProperties`;
- the nested `markdown` property type;
- the schema's required list.

This was a characterization test for already-implemented adapter behavior, so
its first run passed and no production file changed in this fix round:

```console

$ go test -count=1 ./internal/llm -run TestNewChatModel_SerializesStrictJSONSchemaResponseFormat -v

PASS

```

The endpoint is process-local and returns a static OpenAI-compatible response.
It performs no DNS lookup or external network request and generates no content
beyond that controlled response fixture.
